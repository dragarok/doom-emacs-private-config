#+title: How the system works: a day, and the keys

* A day with it
1. *Evening, daily review* (=SPC o v t=, or Today at the 8 PM prompt; C-u
   for yesterday's).  One command, start to end, nothing to navigate.  The
   day's facts are already written; it asks:
   - *Three lines*: one line about today, energy 1-10, first thing
     tomorrow.  Empty Enter skips one.  Anything written closes the review
     as written; nothing written, it closes on its own at 4am.
   - *Date every task* (=SPC o v u=): each undated task in tasks, projects
     and inbox -- =d= a date, =b= break it down, =s= someday, =c= cancel
     (asks why), =x= done, =n= skip.  Ideas are left alone, and so are
     project steps waiting on the one before: finishing that one dates
     them (their TRIGGER).
   - *Plan for tomorrow* (=SPC o v n=): one specific task per daily topic,
     scheduled tomorrow.  Empty Enter skips a topic.
   - The habit month is in the day's facts.
2. *Daytime*: the agenda shows what is dated today.  Clock in (=I=) when you
   start something; agents' work records itself.
3. *Rescheduling* a task the second time asks: break it down instead?
   Yes asks, as in Flow: done when there is what to show, what makes it
   hard, then steps of one sitting each with a result you can see; then
   the first step's day and the all-done-by day (the task's deadline).
   The steps chain like project subtasks: finishing one makes the next
   NEXT, scheduled the day after -- the dates move with the work.
   =SPC o v b= breaks down any task, any time.
4. *Weekly review* (=SPC o v w=): plan the week's topics (=SPC o v o=) and
   read the tables.

Rules the history (2023-2026) earned: a dated task got done 88% of the
time, an undated one 45%; rescheduled twice, 38%.  So every task has a
date, and a task that slips twice gets broken down, not pushed again.

* The idea in one line
Three kinds of time, never added together: *you* (the org clock), *agents*
(recorded on their own), *passive* (music, cleaning).  Reviews show all three.

* What you do
| When                                 | Key                         | Where      |
|--------------------------------------+-----------------------------+------------|
| Work on something yourself           | clock in as always (=I=)    | Mac, phone |
| Start or stop music, cleaning...     | =SPC o v a=, pick or type   | Mac, phone |
| Put an agent on an existing task     | =SPC j o= (optional)        | Mac        |
| Daily review                         | =SPC o v t=                 | Mac, phone |
| Look at today's facts                | Day, on the homepage        | phone      |
| Weekly / monthly review              | =SPC o v w= / =SPC o v m=   | Mac, phone |
| Plan the week's topics               | =SPC o v o= (weekly review) | Mac, phone |
| Plan tomorrow's daily topics         | =SPC o v n= (daily review)  | Mac, phone |
| Add a topic / habit → topic          | =SPC o v s= (=e=: the file) | Mac, phone |
| Pause / resume a topic (away from it) | =SPC o v z=                 | Mac, phone |
| Date every undated task              | =SPC o v u= (daily review)  | Mac, phone |
| Break a task into dated steps        | =SPC o v b=                 | Mac, phone |

That is all.  Everything else happens on its own.

* What happens on its own (Mac)
- An agent working in Herdr → its time goes to its task, in a =:RUNS:= drawer.
  - No task given → the agent names one; else one is made in tasks.org
    (tag =:agent:=) after 2 minutes; shorter runs go to "Agent quick asks".
  - The agent finishes → it renames its own task to what was done, adds a
    summary, marks it DONE.
  - Blocked on you → counted as waiting.
- You looking at an agent in Emacs (=SPC j j=), active → the clock moves to
  its task after 30 s; leave it and your previous task comes back.  Idle 3
  minutes counts as gone.  Clocking in or out yourself always wins.

* Where to see it
- Daily review (day log): "Agents 1h57 on 3 tasks · waited on you 10m · passive 2h30",
  then each agent task with agent / you / waiting time.
- Weekly and monthly review: section "You, agents, passive" — totals, time by
  project, a table of agent tasks, and a chart per day.

* Topics
What I grow in are tags, not habits.  The reviews plan a specific task for
each, and the tables and habit charts show each one like a habit.

*Set up*: =~/org/topics.org= is the whole setup (=SPC o v e= opens it):
#+begin_example
,* Daily
- guitarpractice :: Guitar practice  nf-md-guitar_acoustic
,* Weekly
- mentalmodels :: Mental models
#+end_example
Add a line, or =SPC o v s= (asks tag, daily/weekly, description).  On a
habit in recurring.org, =SPC o v s= turns it into a topic: the habit gets the
tag and is archived with its history.  The icon is optional; a daily topic
with one is in the habit month.

*Plan*: daily topics in the evening's daily review, for tomorrow
(=SPC o v n=); weekly ones in the weekly review (=SPC o v o=).  One question
per topic; each answer is a TODO in tasks.org with the tag, scheduled,
category ToImprove.  Empty Enter skips the topic.

*See*: the Topics tables (days, time, done, planned, "Nothing planned") in
the daily, weekly and monthly reviews; the habit month, calendar and year
show topics as habits (done when a tagged task was clocked or closed that
day, skipped when one was cancelled).  Time on anything with the tag counts,
e.g. the songs in log_guitar.org for guitarpractice -- but they are not
"planned": only open tasks with a date are.

*Pause*: away from the guitar for a while?  =SPC o v z=, the topic, from
when and until when (empty: until you resume it with =SPC o v z= again).
Paused days are grey in the habit charts and ‖ in the Topics tables, count
neither for nor against the topic (a streak runs on across them), and the
planners don't ask about it.  Done on a paused day still counts as done.
The pauses stay under =* Paused= in topics.org, one dated line each:
#+begin_example
,* Paused
- guitarpractice :: 2026-10-25 .. 2026-11-08
#+end_example

*Meetings*: time with a person, never "done".  =meetings.org= has one
heading per person and each meeting is a clock line under it -- no TODO, no
date, so nothing on the agenda.  Clock in on the dashboard (live) or Add >
Clock Time (afterwards), and pick "Meeting: Ram"; a new name asks "a task,
or a meeting with NAME?" ("meeting Ram" skips the question).  Done on the
floating clock asks only for a line of notes, kept under the person with
the date.  The day log shows "Meeting: Ram"; the reviews' time block adds
a *Meetings* line, by person.

* Phone
- Pull the config (code); the org files -- topics.org, the templates,
  tasks -- come over by Syncthing, so Syncthing must be connected too (its
  app on the phone, same network or relay).  "No topics file" = not synced.
- Passive (=SPC o v a=), the clock and the reviews work there.  Agent time is
  recorded on the Mac only (that is where Herdr runs); the phone shows it.
- Avoid editing tasks.org on both at the same minute (Syncthing conflict copy).

* If something looks off
- Herdr won't open in Emacs → already fixed (a daemon restarted from a Herdr
  pane used to inherit HERDR_ENV).
- =M-: agent-time-mode= should be =t= on the Mac.
- Agents get the task tools only in sessions started after the setup.
